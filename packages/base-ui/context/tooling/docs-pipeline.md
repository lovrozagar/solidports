# Docs pipeline

`docs/solid` is fully generated from the upstream React docs snapshot in `docs/react`: sync, generate, validate, build, then crawl the build for route parity and hydration. Never hand-edit `docs/solid`; fix the generator, the transform or the templates.

## Stages

| Step | Command | What it does |
| :--- | :--- | :--- |
| 1 | `bun run docs:sync` | `scripts/docs/sync-docs-react.mjs`: sparse-clones `mui/base-ui@$DOCS_TAG` (default `v1.9.0`, cached under `/tmp`), rsyncs `docs/` into `docs/react`, overlays only workspace paths (Next config, tsconfig, Vitest config, package name `docs`, `pnpm` → `bun`), writes `.upstream-tag`. Then copies the `@mui/internal-docs-infra` source into `docs/docs-infra` at a pinned mui-public commit and runs `extract-error-codes`. |
| 2 | `bun install` | Picks up dependency changes of the new snapshot. |
| 3 | `bun run docs:generate` | `scripts/docs/generate.mjs` writes `docs/solid` (see below). |
| 4 | `bun run docs:validate` | docs-infra's own `validate` (through `framework/docs-infra.mjs`) writes each component's `types.md` API tables and the page indexes below the "autogenerated" marker. Commit the output; CI fails on any diff. |
| 5 | `bun run docs:build` | Production Vite build of `@solidports/docs` (`framework/build.mjs`). |
| 6 | `bun run docs:check-hydration --serve` | `check-hydration.mjs` serves the build on port 3001 and crawls it in Chromium. |

`docs:bootstrap` (root only) chains steps 1–3. `docs:sync`, `docs:generate`, `docs:dev` and `docs:react:dev` exist in both the root and `packages/base-ui` `package.json`. `docs:validate`, `docs:build`, `docs:check-hydration` and `docs:api` exist only in `packages/base-ui`. `docs:api` runs docs-infra validate with `--types`, regenerating only the API tables.

## What the generator does

- Walks `src`, `public`, `scripts` and two root configs of `docs/react`, follows imports, and renames routes `(docs)/react/` → `(docs)/solid/`.
- `.ts`/`.tsx`: `transformReactToSolid` from `react-to-solid.mjs`, then Prettier with the Base UI config. Files under `/demos/` transform as standalone code users copy.
- `.mdx`: transforms ESM blocks and `tsx`/`jsx`/`ts`/`js` code samples, renames `className`/`htmlFor` on JSX attributes, removes excluded sections, and keeps the docs-infra section already in the Solid file.
- Text files get `@base-ui/react` → `@solidports/base-ui` and `/react/` → `/solid/`.
- Generates the reached closure of the source packages the docs import: `docs/docs-infra` → `docs/solid/docs-infra`, `packages/utils` → `docs/solid/base-ui-utils`.
- Writes `docs/solid/package.json` (React-only dependencies dropped, `lucide-react` → `@lucide/solid`, `@tanstack/react-form` → `@tanstack/solid-form`, framework dependencies added), the docs `eslint.config.mjs` and `.gitignore`.
- Copies `templates/` over the output, prunes every file the run did not write (except `types.md` and `__snapshots__`), and writes only changed files, so it runs safely next to `docs:dev`.
- Prints `FAIL <file>: <error>` per file the transform cannot handle and exits 1.

`ADAPTATIONS` in `generate.mjs` holds text edits to generated files, each with a reason; one exists today (`next.config.mjs` page index path). An adaptation that no longer matches throws.

## Templates

`scripts/docs/templates/` supplies what Next.js and React give the React docs:

- `framework/`: the Vite app shell (`App.tsx`, `Document.tsx`, `routes.tsx`, `vite.ts`, `metadata.ts`), `build.mjs`, `docs-infra.mjs`.
- `src/adapters/`: `next/*` (`link`, `navigation`, `image`, `script`, `document`), `react.ts` (React APIs Solid lacks), `react-dom`, `jsx-runtime`, `mdx`, `react-error-boundary`, `test-utils`, `server-only`. `MODULES` in `generate.mjs` maps each import to its adapter.
- `docs-infra/src/`: the hand-written docs-infra runtime. A module there replaces the docs-infra module at the same path; the generator converts what it imports instead. The table of hand-written entries is in `scripts/docs/README.md`.

## Exclusions

`scripts/docs/excluded.mjs` is shared by the generator and the crawler. `EXCLUDED` lists React folders with no Solid page (the private `experiments/` and `playground/` React Server Component pages). `EXCLUDED_SECTIONS` removes page sections and their demos whose library has no Solid 2 version (Combobox and Autocomplete "Virtualized", the React Hook Form section, three Motion animation sections), with `mentions` to strip links to them. Every entry carries a `reason`.

## Fix a demo

1. Find the React demo under `docs/react/src/app/(docs)/react/components/<name>/demos/`. Its output is the same path under `docs/solid/src/app/(docs)/solid/`.
2. Fix the cause, test first (see the TDD rule in `.claude/rules/standards.md`):
   - A React pattern ported wrong: add a failing case to `scripts/docs/react-to-solid.test.mjs`, then fix `react-to-solid.mjs`.
   - Something Next.js or React provides: an adapter in `templates/src/adapters/`.
   - A library with no Solid 2 version: an `EXCLUDED_SECTIONS` entry with its reason.
3. Run `bun run docs:generate` and `bun run docs:validate`, the docs tests, and `bun run typescript --noEmit` in `docs/solid`.
4. Compare `bun run docs:dev` (port 3001) with `bun run docs:react:dev` (port 3005), console open.
5. `bun run docs:build`, then `bun run docs:check-hydration --serve` (or `--origin <url> <route>`).

## Docs-infra bump

`sync-docs-react.mjs` pins `DOCS_INFRA_VERSION` and `DOCS_INFRA_COMMIT` (today `0.13.1-canary.7`, mui-public `73b01ccc61`) and exits when `docs/react/package.json` depends on another version.

1. Find the mui-public commit the new version was published from; update both constants together.
2. `bun run docs:sync`, then diff `docs/docs-infra/src` against the previous snapshot for the hand-written entries.
3. Port each change by hand into `templates/docs-infra/src`, with a failing test beside the module first.
4. Regenerate, validate, and run the `@solidports/docs:dom` tests and the crawl.

Both run with every `test:solid:*` script. A test written under `templates/docs-infra/src` runs from its generated copy, so regenerate before running it.

## CI: "Validating Docs"

The `docs` job in `.github/workflows/base-ui-tests.yml` (60-minute timeout) runs `docs:validate` + `git diff --exit-code`, then `docs:build`, then installs Chromium and runs `docs:check-hydration --serve`. The crawl checks route parity with the React docs (minus `EXCLUDED`); per route a 200 with hydration keys, no logged errors and every server-rendered element claimed by hydration; the first collapsed trigger opening as the same element; and side-nav links preloading on hover.

`scripts/test-all.mjs` runs the same three steps as `docs-validate`, `docs-build` and `docs-hydration`. For hydration internals, see [SSR and hydration](../architecture/ssr-hydration.md).
